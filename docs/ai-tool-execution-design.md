# AI 业务工具与运行恢复设计

状态：设计基线已确认；工具、恢复与界面实现进度以 [AI 生产级改造方案](ai-production-upgrade-plan.md) 为准。以下目标不单独代表已完整实现。

## 工具权限边界

AI 工具可覆盖当前用户在系统业务/管理页面上有权执行的业务操作，包括用户管理、角色授权及页面已有的删除操作；授权事实始终由服务端当前身份和数据权限决定，AI 不可授予自身权限、扩大租户范围或执行页面/后端本身不允许的动作。每次调用及恢复前都要重新读取/核实权限和目标对象状态。

读操作依据权限可自动执行。所有写操作仅需一次明确确认，包括高风险操作；高风险类别、目标对象、影响和风险在同一预览中说明，不另加第二次确认。确认绑定用户、会话/运行、工具、参数摘要及有效期，不能重放到另一操作或另一身份。预约/维护等原有业务条件、照片证据、审批流程照常校验。

## 断点恢复

查询任务中断后自动恢复。写操作中断后，未完成步骤重新预览并要求确认；已成功的步骤返回持久化结果而不重做；外部副作用结果不明时先按幂等键核实/对账，核实前不盲目重试。恢复时重验当前身份、权限、租户和业务前置条件。

模型发起工具调用后，工具结果作为与该调用对应的 ToolMessage/工具角色消息写入会话消息序列，保留工具调用 ID 与结果关联；工具结果不可拼入 system prompt。恢复时从持久化消息/执行账本还原配对。

幂等策略：写操作以运行/确认操作、工具名和规范化参数形成唯一业务幂等记录；确认重试及断点续跑复用同一结果。单次 AI 运行不设工具调用总次数上限。相同参数的只读调用允许实际重试一次；若业务状态与结果仍无变化，则停止该重复调用并向用户说明，不限制参数/状态有变化的后续调用。

## 敏感业务字段

普通模型上下文只保存脱敏占位符。需要原值的业务工具通过服务端短期映射，在明确确认并通过授权后只向指定字段/工具提供；凭据类字段不走此通道。映射不得进入通用消息、checkpoint、向量索引、长期记忆或普通日志；映射过期/遗失时要求用户重新提供。

## 批量写操作：已选 C

- 一项数据库事务可原子完成的批量操作采用整批成功或整批回滚。
- 不能整体回滚的操作，执行前说明部分完成及其影响，拆成独立确认单元；每个单元幂等执行，按项报告结果。
- 续跑逐项核对已完成、未开始和结果不明状态；不得将已成功项再次执行。
- 不同业务前置条件互相依赖的步骤需按依赖顺序执行，前置项失败则暂停依赖项。

## 工具参数验证与修正

工具边界必须确定性校验参数 schema、日期/ID 类型、必填项、对象存在性、租户范围、当前权限及业务状态。验证失败允许结合用户原话和近期上下文由规划层尝试修正一次，再经同一确定性验证；仍有歧义或缺参则向用户追问，不调用工具。写操作始终展示包含规范化参数的预览并经明确确认；高风险操作的风险在同一预览中说明，不另加第二次确认。模型提出的修正不能替代确认。

## 确认后预览发生变化：已选择 B

执行前重新校验身份、权限、目标对象状态和业务规则。若原请求仍合法，操作对象、参数及实际影响均未改变，则按原确认继续；若不再合法则拒绝执行；若目标、参数或影响发生实质变化，则刷新预览并要求用户确认新内容。确认过期直接标为失效，不把旧确认迁移到不同的操作内容。

## 与既有设计决策的关系

本轮“AI 工具范围”选择 C，扩大了 [ADR-0011](adr/0011-agent-tool-safety.md) 记载的工具范围，尤其是账号、角色和删除操作；本轮进一步确认高风险动作仍只需一次明确确认。实现时需新增/修订 ADR，明确预览展示风险、确认绑定操作内容且授权由服务端执行；不得将旧 ADR 误作当前用户已确认的最终范围。
