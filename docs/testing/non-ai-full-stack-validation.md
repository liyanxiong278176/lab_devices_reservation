# 非 AI 全链路测试计划与执行记录

日期：2026-09-28  
范围：FastAPI、MySQL、Redis、Vue 页面及浏览器完整业务链路；不验证 AI 功能，遵守项目 AGENTS.md 的边界。

## 环境与数据原则

- 使用本机 Docker 中的 MySQL 8 和 Redis 7、真实 FastAPI 进程、Vite 页面及 Playwright Chromium。
- 每条端到端场景使用 `e2e-*` 隔离学院、用户和设备；只清理自己的前缀，不修改演示账号或其他学院数据。
- 预约正确性以 MySQL `(device_id, reservation_date)` 唯一约束为准；Redis 锁、页面预检和提示均需与数据库结果一致。
- 性能没有预先约定的固定 SLA 时记录基线和 p50/p95/p99，不虚构“达标”数字；以正确性、成功率、错误分类和资源上限作为门槛。

本节按“执行 → 观察 → 修复 → 重测”追加结果；失败只在相关回归通过后标记关闭。

### 执行结果

- 后端：`ruff check .` 通过；MySQL/Redis 启用的非 AI pytest 为 134 passed、1 skipped（AI 测试排除）。独立 1,000 请求并发用例通过，状态为 201×1、409×47、503×952，数据库未超约。
- 前端：非 AI Vitest 为 13 个文件、69 个测试全部通过；`pnpm build` 通过。构建有 VueUse PURE 注释位置和大 JS chunk 的 Rolldown 警告，未阻断构建。
- 浏览器系统测试：生产预览下 Playwright 14/14 通过。覆盖管理员 CRUD、双标签 CSRF、普通用户预约、审批与履约、报修、通知断线补偿、维护和学院隔离。页面截图位于 `frontend/test-results/`。
- HTTP 冒烟：`/api/v2/live`、普通用户仪表盘、系统管理员总览均为 200；真实 HTTP 10 并发预约为 201×1、409×9，查询数据库确认仅一条设备日期占用。
- 查询基线：在隔离的 100 台设备、10,000 条历史预约数据上，5 并发执行 100 次设备列表、我的预约和第 450 页混合读取，100/100 为 200；吞吐 55.94 req/s，p50/p95/p99 为 77.63/125.21/275.93 ms。该数字是本机 Docker 单实例基线，不是生产 SLA。
- 界面告警修复：管理员更新实验室数据时，Element Plus 表格默认自适应布局会触发一次 Chromium `ResizeObserver loop completed with undelivered notifications`。给实验室表格关闭列宽自适应后，生产预览重跑同一 CRUD 页面不再产生浏览器全局错误；截图确认表格宽度和操作列正常。
- 并发冲突提示回归：预约冲突可能由日期预检或 MySQL 唯一约束兜底返回，两条 409 提示文案不同。用例改为断言两种业务提示之一，并确认失败用户页面无未捕获异常；单项及最终全量浏览器回归均通过。
- 测试框架修复：1,000 请求压测初始队列容量也设为 1,000，未能覆盖 503；将该隔离用例队列容量设为 100 后，稳定覆盖 503 有界拒绝。双标签 CSRF 用例原先依赖 Vite `/src` 动态导入，改为从真实标签页共享存储读取 CSRF 并发同源请求，开发/生产构建均可运行。
- AI 工作台页面审计已从本轮范围剔除；未调用 AI 功能或修改 AI 业务代码。
