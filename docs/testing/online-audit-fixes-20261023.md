# 2026-10-23 线上验收问题修复

对应线上版本 `39d3287` 的六项验收发现。修复已在本地完成，尚未发布到线上。

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 已驳回预约仍在待交接队列 | 查询只过滤交接子状态；驳回也未同步取消交接状态 | 驳回时同步更新预约和交接记录。队列的计数和 ID 分页同时过滤主状态，兼容历史遗留的不一致记录 |
| 设备文档下载 404 | 文档地址已有 `/api/v2`，Axios 的基础地址又添加一次 | 下载前移除已有的 API 前缀，保留相对地址兼容性 |
| 用户端缺少交接异常提示 | 列表统一展示等待交接，详情时间线也未处理 `EXCEPTION` | 列表和详情明确展示交接异常，说明设备暂不能开始使用 |
| 验收完成显示英文 `COMPLETED` | 前端交接状态类型和中文映射只包含旧值 `RETURNED` | 补齐 `COMPLETED` 类型和中文映射，继续兼容旧状态 |
| 报修时间线相差八小时 | MySQL 默认创建时间使用会话本地时区，后续操作显式写 UTC；接口没有标识时区 | 新建报修显式写 UTC，接口以带偏移的 UTC 时间输出，由浏览器转换为当地时间。历史报修优先采用已有 UTC 创建事件，缺失事件时沿用原创建字段，不修改数据库历史 |
| 预检 422 产生未捕获异常 | 监听器异步调用预检，但只使用 `finally` 收尾 | 捕获失败，清除不可用的预检结果，持续展示服务端原因；更换日期后重新检查，忽略过期请求的失败 |
