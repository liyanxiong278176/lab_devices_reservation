# 非 AI 综合验证记录（2026-09-29）

## 范围与方法

本轮验证预约、学院隔离、实时通知与断线补偿、用户管理、设备交接和归还验收；AI 目录及模型调用不在范围内。测试策略按风险和测试层级组合单元、接口、MySQL/Redis 集成、真实页面链路、安全探测和小规模性能验证。参考了 [ISTQB CTFL 4.0.1](https://istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf)、[OWASP Web Security Testing Guide](https://wstg.owasp.org/latest/2-Introduction/)、[Playwright locators](https://playwright.dev/docs/locators)、[Playwright assertions](https://playwright.dev/docs/test-assertions)、[Grafana k6 性能测试指南](https://grafana.com/docs/k6/latest/testing-guides/automated-performance-testing/) 和 [WCAG 2.2](https://www.w3.org/TR/wcag/)。

多账号联调使用三份全新 Chromium context 和本轮专用 Node 页面脚本，未运行仓库现有 Playwright spec。两名普通用户和系统管理员都从真实 Vue 页面操作；使用隔离学院、隔离账号、设备和日期，结束后清理业务数据并保留页面截图与 JSON 记录。

## 三账号真实页面链路

测试日期为 2026-09-29，学院为本轮隔离学院 656：

1. 用户 A 在真实预约页面预约共享设备 `#11935`，申请 `#71538` 创建成功，页面显示待审批。
2. 用户 B 对同一设备、同一自然日提交时收到预期 `409 RESERVATION_CONFLICT`，页面保留申请上下文；改选备用设备 `#11936` 后，申请 `#71539` 创建成功。
3. 管理员核对两条申请的申请人、用户 ID、设备、日期和学院，分别审批并完成交接。两笔记录进入使用中，配件“电源线”状态正常，交接照片已上传。
4. B 离线期间管理员完成审批和交接。B 恢复连接后，通知历史从 1 条变为 4 条，新增审批、交接和预约提醒 3 条，没有重复；未读状态同步为 4。B 的通知查询曾遇到 access token 过期 401，随后 `/auth/refresh` 返回 200，原通知请求重试 200，页面成功加载。
5. A、B 分别从真实用户页面提交正常归还，管理员逐笔核对申请、设备、用户、日期和附件后验收。归还附件通过同源读取确认均为 HTTP 200、`image/png`；管理员页面待验收队列清空。
6. 两名用户各自刷新“我的预约”和详情页，最终均看到“已完成 / 已完成归还验收 / 验收正常”。数据库只读复核为两笔预约 `COMPLETED`、交接 `RETURNED`、设备 `IDLE`、未验收交接 0 条。

WebSocket 诊断严格区分了模拟边界：10 秒浏览器离线模拟没有关闭既有 socket；随后在同一 SPA 页面受控关闭 `/api/v2/ws` 实例，应用在 5.025 秒后自动创建并打开新连接，重连后的未读请求为 200。这个结果验证了 socket 关闭后的重连路径；不能表述成“浏览器离线本身已触发 socket close”。A 的在线通知中心和未读徽标有更新，但审批/交接 toast 未在出现时留存截图。

## 本轮发现与修复

管理员用户管理页先展示用户数据、后加载学院映射，存在短暂把有学院归属的账号显示成“全局”的界面竞态。调整了 [用户管理页](../../frontend/src/views/user/Index.vue)：学院映射加载完成后才发布新用户行，并新增受控延迟学院请求的回归用例。针对性用户管理测试 10 项通过，`pnpm build` 通过；真实管理员页面刷新后，用户行从加载开始即显示目标学院，编辑表单也选中学院 656。

多账号执行中还修正了若干临时 runner 的等待和定位问题（列表刷新时机、申请字段断言、包含两个 `span` 的宽定位器、附件新标签页关闭），这些是联调脚本问题，没有导致错误审批、重复提交或错租户写入。

测试隔离数据已清理：学院、测试用户、预约和该学院通知均为 0 条；80 份页面/运行证据仍保留在 `frontend/.artifacts/manual-agent-fresh-2026-09-29/`。

## 覆盖边界与后续建议

- 这轮没有完成正式 WCAG/axe 键盘、对比度和屏幕阅读器审计；页面视觉与主要操作只在本轮桌面 Chromium 链路中检查。WCAG 2.2 仍可作为后续无障碍验收基线。
- 1,000 请求组出现 870 个 503，说明有界过载保护在起作用，但还需要用固定环境、明确通过阈值的 k6 场景测量持续吞吐、错误率、延迟分位数和恢复时间，再讨论生产容量。
- 浏览器离线模拟没有让已建立 WebSocket 在 10 秒内关闭；本轮用同页受控 close 验证自动重连，同时用离线前后通知历史验证补偿。若需要证明真实网络断开触发 close，应再增加可控网络代理/服务端断连实验。
- 后端默认套件仍显示 19 个 skip，虽然相关 MySQL/Redis 非 AI 集成组已单独执行并通过；CI 应显式配置这些依赖组，避免日常流水线漏跑。
- 当前没有发现上述测试范围内仍未解决的功能缺陷；这不等于系统已被证明无缺陷，也不替代生产环境容量、全浏览器兼容性和更全面无障碍审计。
