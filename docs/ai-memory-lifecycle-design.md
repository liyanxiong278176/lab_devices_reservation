# AI 记忆生命周期设计

状态：设计基线已确认；记忆实现与验收进度以 [AI 生产级改造方案](ai-production-upgrade-plan.md) 为准。以下规则不单独代表已完整实现。

## 分层与确认

- L0：原始对话。
- L1：按场景划分的事实记忆，自动提取有来源依据的事实。
- L2：用户画像、长期偏好和约束，候选经用户确认后保存。
- 优先使用相关 L2，信息不足时再检索 L1/L0；记忆不能替代实时权限及业务数据。
- L0/L1/L2 全部按用户隔离，不提供自动或显式跨用户共享。向量查询、关键词查询、归档检索、记忆管理及恢复均须绑定当前 user_id；只有用户本人的记忆可进入该用户上下文。

## 有效召回

记忆实际参与回答或决策，或用户明确确认其有用，任一条件满足即可计数。同一轮同一记忆最多一次；两个条件同时满足、重试和重复检索不额外计数，仅进入候选列表也不计数。

## 已选有效期方案 B：增益递减

三层均从 180 天初始有效期开始。令 n 为累计有效召回次数，采用与已确认选项数值对应的公式：

`ttl_days(n) = min(360, 180 + 60 * log2(1 + n))`

没有有效召回时从创建时间计时；有有效召回时从最近一次有效召回时间计时。公式结果转换为时间间隔计算到期时间，不依赖展示时的天数取整。

| 累计有效召回次数 | 有效期 |
| --- | --- |
| 0 | 180 天 |
| 1 | 240 天 |
| 3 | 300 天 |
| 7 及以上 | 360 天 |

360 天限制最近一次有效召回后的有效期，不限制持续有效使用的记忆的总存续时间。这是工程策略，不宣称复现人的遗忘曲线。

## 归档与删除

到期先归档，归档后连续 180 天未使用才最终删除，替代原先正文创建满 180 天直接删除的目标规则。只有用户明确追溯历史时才检索归档；通过当前权限及纠正、失效状态核验并实际使用后恢复活跃。用户仍可主动删除记忆，业务操作审计与对话正文分别保留。

删除一段 L0 原始对话时，不级联删除由其提取的 L1/L2 记忆；记忆继续按各自 TTL、归档和最终删除规则管理。用户可独立主动删除某条记忆。记忆须保留来源关联以便追溯；用户删除原文后，来源关联只允许指向不可恢复的来源标识，不得借此恢复原文。

## 更正与事实冲突

用户明确纠正某事实时，将原记忆标记失效，不再作为当前事实参与召回；保留可追溯的更正关系。一般信息发生冲突时保留双方来源与时间，不擅自以“较新”或“召回更多”判真；若答案取决于冲突事实，向用户澄清。L2 长期偏好/画像依然遵循候选确认规则。

## 用户管理入口：已选 C

不提供独立的记忆管理页面。用户可在对话中纠正记忆；系统应定位被纠正的记忆并使旧事实失效，若指代不明确则先询问。用户可在对话中主动删除记忆：系统先展示匹配目标并请求一次确认，确认后删除；若范围或目标不明确，先追问，不猜测删除对象。用户要求遗忘某个主题时，清除该主题下相关的 L1/L2 记忆及其派生副本；L0 原始对话仍按独立生命周期保留，不级联删除。

## 尚待细化

- 召回强化不得复活已纠正或已失效的事实；实现与验收需覆盖此边界。
