# AI 回答输出验证设计

状态：设计基线已确认；DLP、引用校验与输出链路的实现进度以 [AI 生产级改造方案](ai-production-upgrade-plan.md) 为准。以下目标不单独代表已完整实现。

## 输入侧已确认行为

用户选择自动脱敏后继续：识别到的 API Key、密码、手机号、身份证号等敏感内容替换后再发送模型，页面仅提示已脱敏类别，不回显敏感原文。无需每次确认脱敏预览，不提供凭据原文发送模型的选项。

DLP 范围覆盖所有发往模型的内容：用户消息、附件经解析/OCR 得到的文本、RAG 检索片段、L0/L1/L2 记忆和业务工具返回值。每个数据来源进入模型前经过同一检查边界；不得因内容由内部系统生成而假设不含敏感数据。

用户已选择：知识库原始文件仍按现有流程上传给 MinerU 解析，上传前不做本地 DLP；MinerU 返回的解析文本必须在进入聊天模型、Embedding、RAG 上下文或记忆前经过统一脱敏。这代表管理员批准的 MinerU 原件处理是明确例外，不能宣称原始上传文件已由 DLP 脱敏。页面及配置说明应告知该文件处理边界。

日志、普通聊天持久化和记忆提取路径应使用脱敏内容，防止这些路径绕过模型入口脱敏；L0 的全量保留指保留完整对话序列，不等于保留误贴的凭据明文。

## 已确认的敏感业务字段通道

模型只看到占位符，业务确实需要的原值由服务端短期保管，映射绑定用户、运行及字段。用户明确确认操作后，服务端重新校验当前权限、目标对象、指定工具和字段用途，将原值交给指定工具；密码、API Key 等凭据不进入这一通道。

实现须阻止伪造占位符、跨用户/运行复用、换工具或字段套用，以及借工具结果回显原值。原值不得写入通用消息、checkpoint、检索索引、长期记忆或普通日志；映射过期或丢失时请求用户重新提供，不让模型猜测或从旧历史恢复。恢复执行仍遵循未完成写操作重新确认的规则；短期保管期限和加密存储方式在实现设计中细化。

## 已确认行为

回答在服务端缓冲成段，经 DLP 与适用的事实引用校验后逐段展示。涉及业务数据的事实须关联可点击证据：先确定性检查引用存在、可访问，再检查原子事实是否得到证据支持；不支持的事实不输出。

用户已选择引用点击后打开侧边详情：知识引用显示受 ACL 约束的原文片段及章节/页码；业务数据引用显示对应记录详情。引用目标从服务端核验过的 ID 生成，不信任模型提供的任意链接或 ID。

## 实现约束与验收要点

- 模型原始 Token 不直接转发浏览器；进度事件和最终回答内容采用不同事件类型。
- 分段并非逐段独立判断：检测必须保留跨边界上下文，不得因手机号、凭据或事实跨段而漏检；尚不能确定安全或证据充分的内容继续缓冲。
- 输出事实依赖后续文本才能核验时延迟发布。流结束时检查剩余缓冲，验证失败不能改为直接输出原文。
- 引用按当前访问权限及版本核验，不能用模型自行生成的来源标识作为存在性或授权依据。
- 将回答拆成可核验的原子事实；事实只有在引用确实支持时才保留，无法支持的原子事实删除，保留同一回答中有依据的其他事实。不得将“模型觉得相关”作为引用通过标准。
- 业务数字、日期、状态优先与结构化工具证据做确定性核验；语义支持判断不能作为数学证明或代替服务端授权。
- 断线重放与历史消息读取只交付经过验证的可展示内容；敏感原始输出不得通过进度、异常或调试事件泄露。
- 验收覆盖跨段敏感信息、伪造或越权引用、无依据事实、校验故障、尾段输出及重连重放。
