# ADR-0019：本次先实现程序级高可靠

- 状态：已接受
- 日期：2026-08-26
- 决策人：项目负责人

## 决策

本次重构暂不设计生产部署节点、负载均衡、数据库集群或多机容灾。高可用目标限定为应用程序级可靠性：

- 单个请求、Agent、任务或外部依赖失败不能拖垮其他请求；
- 预约并发冲突必须得到确定且正确的结果；
- 业务写入、通知、超时和索引任务具备幂等、重试和重启恢复；
- Redis、Qdrant、模型供应商或 WebSocket 连接异常时有明确降级和可观测错误；
- 服务重启后可以恢复未完成的业务任务和 AI 会话状态；
- 通过并发、故障注入、恢复和性能测试证明行为，而不是仅依赖部署配置。

生产基础设施级高可用（多节点、数据库副本、负载均衡、备份演练）作为后续部署阶段单独规划，不在本次应用重构中假设已经实现。

## 影响

- 代码必须有明确的超时、熔断/舱壁、连接池、任务领取、条件更新和恢复机制。
- 测试需要覆盖依赖不可用、服务重启、重复消息、并发抢占和部分失败。
- 最终验收仍需定义可重复的并发量、延迟和错误率阈值，避免“高性能/高可用”成为无证据的描述。
