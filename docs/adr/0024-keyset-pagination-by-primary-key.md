# ADR-0024：高增长列表采用主键游标分页

预约、通知、报修等持续增长的业务列表采用 Keyset Pagination：当前端按最新记录倒序浏览时使用 `id < last_id`、`ORDER BY id DESC` 和 `LIMIT` 查询，不使用大偏移量分页。`id` 主键索引已由数据库提供；带学院、状态等过滤条件的查询根据实际访问路径建立组合索引。需要按创建时间排序时，使用 `(created_at, id)` 作为稳定排序和游标。小规模目录数据仍可使用页码分页。

前端可以保留页码式视觉交互，但页码必须由已访问页面的游标链驱动：已缓存游标的页面直接请求，未访问的深页按游标顺序补齐，不允许为了任意跳页重新退回大 `OFFSET` 查询。筛选条件、排序方式或页大小变化时，必须清空游标链。

## Consequences

- 深页查询不需要扫描并丢弃大量前置行，延迟更稳定。
- 前端可以保留页码外观，但未建立游标链的深页跳转需要顺序补齐，不能承诺瞬时跳转任意页。
- 游标排序字段必须固定，组合过滤条件必须通过 `EXPLAIN` 验证索引命中情况。
