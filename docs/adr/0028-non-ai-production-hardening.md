# ADR-0028：非 AI 预约业务生产级加固

- 状态：已接受
- 日期：2026-09-21
- 范围：认证、学院隔离、自然日预约、履约、设备、报修、通知和异步任务

## 决策

1. FastAPI 是唯一后端实现，旧 Java/Maven/Spring Boot 构建与源码不再保留。
2. 预约继续以自然日为最小冲突单位，唯一事实键是 `(device_id, reservation_date)`。
3. 签到和归还属于预约状态机的一部分。签到/归还写入审计时间；归还必须保存验收结果，异常会将设备置为维护状态。
4. 设备状态变化必须记录原状态、新状态、操作人和原因；维修期间禁止恢复为空闲或继续预约。
5. 取消、拒绝和爽约释放日期后，通过持久化 Outbox 通知候补队列首位用户；候补用户必须重新提交预约，系统不静默替他占用设备。
6. 学院、实验室和设备可以配置自然日不可预约日期，预约预检和创建使用相同规则。
7. Refresh Token 使用数据库会话记录进行轮换和撤销；Access Token 依赖每次读取当前用户状态和角色。
8. 通知表是历史事实源，FastAPI 原生 WebSocket 仅做实时提示，断线后由 HTTP 查询补偿。
9. 用户取消与负责人驳回使用不同终态；完成归还后允许一次性设备满意度评价，评价按学院和管理范围隔离。

## 取舍

- 本轮不引入新的部署服务；候补、通知、信用扣分和缓存失效继续在单体 Outbox 中执行。
- 候补通知不自动创建预约，避免绕过用户确认、审批和幂等协议。
- 预约选择仍不暴露时分秒；精确时间只用于审计、任务执行和故障排查。
- AI Agent、LangGraph、RAG、Qdrant 和模型配置不在本 ADR 的实现范围内。
