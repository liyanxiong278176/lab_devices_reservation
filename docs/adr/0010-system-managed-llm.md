# ADR-0010：由系统统一管理大模型配置

- 状态：已接受
- 日期：2026-08-26
- 决策人：项目负责人

## 决策

大模型供应商、API Key、模型名称、基础地址和额度由后端 `.env` 配置，运行时只从进程环境读取；数据库不保存 Provider 配置或 API Key。修改 `.env` 后需重启后端。AI 工作台只展示配置状态并提供连通性测试，不回传或编辑密钥。用户不能在前端提交自己的 API Key，也不能让服务端请求任意用户提供的模型地址。

系统维护允许使用的模型白名单，并按用户、学院和模型设置请求频率、并发、token/成本预算和每日额度。前端 AI 工作台可以展示当前可用模型和剩余额度，但不能暴露密钥。

所有模型调用必须经过统一 Provider/Gateway 适配层，记录 provider、model、耗时、token、错误和成本摘要，禁止在 Agent 工具中散落直接调用供应商 SDK。

## 影响

- 密钥生命周期由部署配置管理，数据库泄露不包含模型供应商凭据。
- 部署和运维更集中，适合校园内部系统。
- 可以统一做模型降级、超时、重试、限流、成本控制和审计。
- 用户失去自带模型的灵活性；未来如需开放，必须新增加密存储、域名/IP allowlist、SSRF 防护和租户级预算，不能直接开放任意 `base_url`。
