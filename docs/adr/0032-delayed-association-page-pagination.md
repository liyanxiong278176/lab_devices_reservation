# ADR 0032：列表页码直跳采用延迟关联

## 状态

已采用。

## 背景

ADR 0024 采用主键游标避免深 OFFSET，但页码界面要访问未加载的第 N 页时，只能先顺序请求第 1 至 N-1 页，无法直接跳页。管理端和业务列表需要保留页码直达能力。

## 决策

1. 所有已有游标分页列表及实验室管理列表改为直接接收页码；`/api/v2` 不再接受分页游标参数。
2. 使用稳定的 `id DESC` 排序，在子查询中只选择满足筛选和学院/负责人授权条件的主键并应用 `LIMIT/OFFSET`；再与主表关联读取本页完整记录。
3. 真实匹配总数照常返回；每个请求最多跳过 100,000 条匹配记录。可访问页数受限时，响应标记 `truncated`，前端显示明确的筛选提示。
4. 结果筛选、租户权限、排序和总数统计继续由服务端执行，不依赖前端隐藏或裁剪记录。

## 结果

- 用户可直接访问允许范围内的任意页，不再为逐页建立游标链等待多次网络请求。
- 深页只对主键索引窗口执行 OFFSET，再读取当前页完整行，减少跳过记录时的宽行读取。
- 延迟关联不会让 OFFSET 成为 O(1)：数据库仍需扫描被跳过的索引项，因此 100,000 条硬上限仍由服务端执行。
- 该决策取代 ADR 0024 对业务列表游标链的要求；顺序流/滚动加载若未来出现，应作为独立接口重新评估。
