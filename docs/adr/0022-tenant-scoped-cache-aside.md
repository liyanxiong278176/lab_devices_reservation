# ADR-0022：采用学院隔离的 Cache-Aside 缓存策略

Redis 缓存设备、实验室、分类等读多写少的目录数据，以及允许短暂陈旧的推荐/统计结果；预约日期可用性另由 ADR-0038 定义的设备日级名额缓存做快速预检，MySQL 预约记录和设备日期唯一约束仍是最终事实与防超约依据。审批状态和权限判断始终以 MySQL 为准。缓存键必须包含学院范围和必要的用户范围，写事务提交 MySQL 后同步推进对应学院的目录缓存版本；同步失效失败不回滚数据库写入，持久化 Outbox 任务负责重试，TTL 作为最终兜底。缓存读取采用随机 TTL、空值短缓存和热点 Key 互斥加载，必要的稳定目录数据支持预热；目录缓存读取失败或 Redis 不可用时回源 MySQL，预约名额缓存未命中或不可用时走 MySQL 预约路径。

## Consequences

- 目录缓存不会成为预约一致性和权限判断的事实来源；预约名额缓存只用于快速预检和并发预占，MySQL 唯一约束仍是防超约的最终保障。
- 预约名额缓存若短暂低估可用量，可能先行拒绝请求，周期性 MySQL 对账会重建缓存；Redis 未命中或不可用时直接走 MySQL。
- 学院范围进入缓存键，避免跨学院数据串读。
- 设备、实验室和分类变更需要维护缓存失效关系；统计类缓存允许通过 TTL 最终过期。
- 正常写入完成后设备列表立即切换到新缓存版本；Redis 故障只会让本次读请求回源 MySQL，不阻塞设备管理写入。
- 空值缓存降低不存在数据造成的缓存穿透，互斥加载降低热点 Key 过期造成的缓存击穿，随机 TTL 和预热降低集中失效造成的缓存雪崩。
