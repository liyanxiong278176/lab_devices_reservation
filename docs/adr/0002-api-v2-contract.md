# ADR-0002：以 `/api/v2` 作为新系统外部接口

- 状态：已接受
- 日期：2026-08-26
- 决策人：项目负责人

## 背景

现有 Spring Boot 接口是在功能逐步增加的过程中形成的，REST 返回结构、错误处理、分页和实时消息协议存在历史包袱。此次后端和前端都要重构，如果强行保持旧接口，会把旧的边界问题带入 FastAPI。

## 决策

新系统使用 `/api/v2` 作为 REST 和实时通信的版本边界，由 FastAPI 与新版前端共同实现新契约。接口可以重新组织资源、请求/响应模型、错误结构、分页、幂等和实时事件，但必须保持以下领域语义：

- 预约生命周期和合法状态转换不变，除非后续领域建模明确修改。
- 用户、角色、权限和资源归属规则不因接口重设计而放宽。
- 原有核心业务目标（设备预约、审批、签到、使用、归还、通知、维修和 AI 辅助）必须继续可用。

旧 `/api` 不作为新系统的兼容承诺；回滚依赖旧版本制品和数据库备份/兼容迁移，而不是在新服务中长期保留两套接口。

## 约束

- OpenAPI/JSON Schema 作为接口事实来源，前端类型和接口测试从契约生成或校验。
- 写操作必须在契约层明确幂等语义、并发冲突响应和权限失败响应。
- WebSocket/SSE 等实时协议必须有版本、事件类型、序列号、重连和补偿规则。

## 影响

### 正面影响

- 可以统一错误、分页、鉴权、幂等和实时消息模型。
- 前端 AI 工作台能够采用适合流式 Agent 事件的协议，不必迁就旧悬浮球接口。
- 接口边界清晰，便于后续性能压测、契约测试和独立演进。

### 代价与风险

- 前端和后端必须同步完成适配，回归范围大。
- 一次性切换时不能依赖旧接口作为线上兼容层，必须先完成契约测试和回滚演练。

## 未决问题

资源路径、鉴权方式、错误码、实时协议以及是否保留 `/api` 作为容器上下文前缀，在 API 设计阶段细化。
