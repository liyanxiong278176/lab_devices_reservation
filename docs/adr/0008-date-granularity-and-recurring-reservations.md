# ADR-0008：预约采用自然日粒度并支持重复/批量预约

- 状态：已接受
- 日期：2026-08-26
- 决策人：项目负责人

## 背景

现有实现以分钟槽位表达预约，用户要求预约时间不要细到时分秒，而是以天为单位；实验室实际使用还需要支持连续多日或每周重复的预约。

## 决策

预约领域时间统一使用自然日：

- 用户输入 `start_date` 和 `end_date`，按首尾包含解释；不提供开始/结束时刻。
- 设备冲突的最小单位是 `(device_id, reservation_date)`，同一设备同一自然日最多有一个有效占用。
- 连续多日预约会覆盖日期区间内的每一天。
- 重复/批量预约由一个用户操作生成一组具有关联标识的独立预约记录；每个日期分别执行学院范围、设备状态、审批和幂等校验。
- 提交前必须进行全量预检，并明确展示可用日期和冲突日期；用户可以选择只提交可用日期，或放弃整个批次，系统不得静默丢弃冲突日期。
- 原有分钟槽位数据迁移时按有效预约覆盖的日期折叠为日期占用；无法无损判断的历史记录进入人工核验队列。
- `created_at`、`updated_at`、审批时间和审计时间可以保留精确时间，用于追踪和故障分析；这些字段不暴露为预约选择条件。

## 尚待确定

批量预约遇到部分日期冲突时，采用“预检 + 用户明确选择”的策略：可提交日期部分提交，或用户放弃整个批次；冲突日期必须可追踪并返回明确原因。

## 影响

### 正面影响

- 预约表单和日历更容易理解，用户不需要处理分钟槽位。
- 冲突唯一键和并发验证更简单，减少时间边界、时区和跨天计算错误。
- 重复预约可以直接以日期集合展示和管理，适合课程、实验计划和连续使用。

### 限制与风险

- 同一设备一天内不能被不同用户分时共享；如果未来需要半天或小时级预约，必须升级领域模型和冲突索引。
- 批量操作需要明确部分成功、审批、取消和通知语义，不能把多条预约伪装成一次不可分割写入。
