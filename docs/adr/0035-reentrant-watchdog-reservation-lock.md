# ADR-0035：为预约日期锁增加可重入租约与看门狗

后端保持 Python/FastAPI，不引入 Java Redisson；预约锁在现有 Redis 客户端上实现等价的持有者、可重入计数和租约续期语义。锁持有者标识为应用实例与当前 asyncio Task，Redis Lua 原子完成加锁/重入计数、持有者校验释放和租约续期；持有上下文存活时，看门狗按租约周期续期。多日期锁继续按日期排序并在部分获取失败时回滚已获取锁，MySQL `(device_id, date)` 唯一约束仍是预约正确性的最终保障。

## Consequences

- 同一 asyncio Task 可安全嵌套获取同一日期锁；其他 Task 即使属于同一用户仍会竞争同一资源锁。
- 固定 TTL 变为看门狗维护的租约；应用任务结束或看门狗无法确认持有权时停止续期，Redis 故障和锁过期仍由 MySQL 唯一约束兜底。
- 看门狗不能阻止已失去租约的旧任务继续运行，因此 Redis 锁只协调流程，不取代数据库事务、唯一约束或条件更新。
- Redis 锁值格式升级期间，旧版随机 token 会被新版视为其他持有者，直到其 TTL 到期；锁键命名空间保持不变以避免滚动期间绕过彼此的锁。
