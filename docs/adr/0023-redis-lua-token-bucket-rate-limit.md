# ADR-0023：采用 Redis Lua 令牌桶进行分级限流

为保护单体 FastAPI 服务、数据库和外部依赖，本轮对登录、预约、报修等接口采用 Redis Lua 令牌桶限流。限流维度包括接口、用户、IP 和学院，具体阈值按接口类型配置；Lua 将额度检查、扣减和过期时间设置作为一次原子操作，超限统一返回 429 和 `Retry-After`。AI 相关请求不属于本轮限流范围。Redis 失效时，普通查询、预约和报修降级到进程内临时限流并继续依赖数据库保护；登录使用进程内 IP 限流和账号失败次数控制，Redis 恢复后自动回到共享限流。

认证后的常规页面查询采用较大的默认突发额度（默认 300 次、每秒恢复 5 次），避免同一校园出口或学院内多个正常用户因页面并行加载而互相限流；预约和报修写操作继续使用独立的较严格额度。登录限流拆分为来源 IP（默认 30 次/分钟）和账号（默认 5 次/分钟）两个桶，避免校园 NAT 下用户之间共享 5 次登录额度，同时保留针对单账号的暴力尝试保护。调整策略时使用新的 Redis bucket namespace，避免沿用旧阈值耗尽的 token 状态。

## Consequences

- 多个应用进程共享同一套限流状态，避免单进程计数失真。
- 突发流量可以消耗桶内已有额度，持续高频请求会被平滑限制。
- Redis 故障时需要明确降级策略，不能让限流组件直接阻断预约核心链路。
- 阈值必须通过真实基准和压测调整，不能把示例数值直接当作最终生产配置。
