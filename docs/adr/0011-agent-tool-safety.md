# ADR-0011：Agent 采用读自动、写确认的工具安全策略

- 状态：已接受
- 日期：2026-08-26
- 决策人：项目负责人

## 决策

Agent 工具按副作用分级：

- 只读工具（搜索设备、查询日历、查询本人预约、检索知识库、查看统计）可以在权限范围内自动执行。
- 写工具（创建/取消预约、提交报修、审批、处理报修、修改设备）必须先生成结构化的待确认动作，展示目标对象、学院范围、日期、影响和风险，用户明确确认后才能执行。
- 系统权限变更、用户管理、跨学院操作和不可逆数据操作不直接开放给 Agent；可以由 AI 解释规则、生成草稿，最终由专用后台界面完成。

确认不是授权替代品：工具执行前后都必须在后端重新校验当前用户、学院、实验室范围、对象状态、幂等键和并发条件。确认动作必须绑定用户、会话、工具参数摘要和过期时间，防止篡改、重放或跨用户执行。

## 影响

- AI 能够真正完成预约和报修等业务，但不会出现“模型说执行了、系统实际未执行”或无确认副作用。
- 前端需要渲染步骤、参数和风险确认卡片，并处理过期、冲突、失败和重试状态。
- Agent Harness 必须保存工具调用、确认、执行结果和审计轨迹，支持断线恢复和评测。
