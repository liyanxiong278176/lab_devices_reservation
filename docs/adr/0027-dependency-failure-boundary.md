# ADR-0027：区分 Redis 可降级故障与 MySQL 事实源故障

Redis 只承担缓存、分布式锁和限流等辅助职责，因此 Redis 不可用时，缓存读取回源 MySQL，预约继续依赖数据库唯一约束，限流退化到进程内策略。MySQL 是业务事实来源；当数据库不可用、连接池耗尽或事务无法确认时，系统对需要事实数据的请求快速返回结构化 503，不使用过期缓存伪造预约、权限、审批或设备可用性结果。所有 Redis 调用设置短超时和熔断，避免辅助依赖拖慢核心请求。

## Consequences

- Redis 故障不会直接扩大为预约系统不可用。
- MySQL 故障时优先保证数据正确性，不以陈旧数据换取错误的业务成功。
- 需要分别监控 Redis 降级次数、MySQL 失败率、连接池耗尽和恢复时间。
