# ADR-0020：以基准测试驱动性能验收

- 状态：已接受
- 日期：2026-08-26
- 决策人：项目负责人

## 决策

不在未测量的情况下预先承诺固定 QPS 或 p95 数字。先使用接近真实的设备、学院、预约和知识库数据建立基准，再依据资源配置制定可重复的验收阈值。

基准测试必须至少覆盖：

- 同一学院、同一设备、同一自然日的高并发预约，验证唯一成功、无重复占用和正确冲突响应；
- 设备检索、日历、预约列表、审批列表等读 API 的吞吐、延迟、连接池和缓存命中；
- AI 请求高峰与预约 API 并发时的资源隔离和尾延迟；
- Redis、Qdrant、模型供应商、数据库连接短暂失败时的降级、超时和恢复；
- 服务重启、重复任务、重复确认和网络断线后的任务/会话恢复。

验收报告同时记录成功率、p50/p95/p99、错误分类、数据库锁等待、连接池使用、队列积压、模型耗时/token 和恢复时间。不得只用“请求返回 200”证明高性能或高可用。
