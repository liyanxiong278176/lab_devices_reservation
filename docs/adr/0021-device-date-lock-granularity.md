# ADR-0021：预约并发锁采用设备日期级粒度

预约冲突的领域最小单位是“设备 + 自然日”，因此 Redis 协调锁采用 `device_id + reservation_date` 作为锁键，而不是锁住整个设备。批量预约按日期排序后依次获取锁，以减少同一设备不同日期之间不必要的排队并避免锁顺序不一致；MySQL 唯一约束仍是最终防超约依据。Redis 锁只用于降低并发竞争，Redis 故障时请求继续由数据库事务处理。

## Consequences

- 同一设备不同日期可以并行预约，提高日期级并发度。
- 多日期批量预约需要统一加锁顺序，并设置超时和释放逻辑。
- 锁粒度优化不能替代数据库唯一约束和幂等处理。
