# ADR 0029：自然日预约的履约、资产与运维闭环

## 状态

已采用（非 AI 范围）。

## 背景

系统已经具备按学院隔离的设备预约、审批和基础报修能力，但设备资产标识、外借交接、风险准入、维修确认和运营导出如果只停留在页面提示，实际使用时仍会出现“预约结束后无法复用”“外借无责任交接”“维修被误关单”等问题。

## 决策

1. 预约仍以自然日为最小单位；`v2_reservation_day` 只记录有效占用。预约完成、取消、驳回或终态处理后释放占用行，历史预约本身保留。
2. 不外借设备继续使用预约、审批、签到、使用、归还流程；允许外借的设备在审批后进入负责人交接，归还后进入负责人验收，再完成预约。
3. 设备维护、停用、离线和报废状态禁止新预约；设备资产使用独立资产编号和随机 QR token，数据库自增 ID 只作为内部标识。
4. 高风险设备可以要求最新版安全须知确认；特别高风险设备还需负责人审核培训/资质材料并设置有效期。普通设备不增加额外门槛。
5. 报修处理结果先进入 `RESOLVED`（待用户确认），用户确认后进入 `COMPLETED`；用户退回时重新进入 `PROCESSING`。优先级决定 SLA，未确认工单由持久化任务在三个自然日后自动关闭。
6. 报表按负责人可管理的学院/实验室范围查询。小数据同步 CSV，大数据写入导出任务并由 outbox worker 生成文件；所有导出写审计记录。
7. SOP 和安全须知以系统内文档版本保存，并为现有设备生成可追溯的 Markdown 初版；不改变 AI 模块和 AI 数据链路。

## 结果

- 新增字段和表只通过 `V15` 及之后的 Alembic 迁移加入，既有预约和历史审计不被删除。
- 设备、预约、交接、报修和导出都继续走学院/实验室授权校验，状态变更集中在应用服务层。
- 浏览器端提供摄像头二维码扫描，同时保留手工 token 输入作为无摄像头回退。
- 管理员可以用运营报表页面验证设备、预约和报修闭环；AI 不在本决策范围内。
