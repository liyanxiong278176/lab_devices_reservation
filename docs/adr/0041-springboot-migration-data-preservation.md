# Spring Boot 迁移保留现有业务数据

状态：已接受并实施；业务数据保留策略、非 AI 功能完整兼容要求及后端切换方式已于 2026-10-13 由用户确认。

用户要求移除当前项目的全部 AI 功能，并将 Python/FastAPI 后端迁移到 Java/Spring Boot。本次迁移保留现有业务数据，不以全新空库替代现有数据库；账号、权限、学院、实验室、设备、预约、履约、报修、维护、通知及业务关联记录应纳入迁移保护范围。

保留业务数据会增加数据库兼容和迁移验证成本，但可避免已有业务历史与关联关系丢失。

用户确认完整兼容现有非 AI 功能和接口行为。继续使用 Vue 前端及 `/api/v2`，保留预约审批、交接验收、报修维护、权限与学院隔离、通知、报表，以及当前认证和并发保障。现有非 AI 页面、业务规则和测试作为 Spring Boot 后端的兼容验收依据；移除 AI 所需的前端调整属于本次范围。

用户确认先完成 Spring Boot 并验证，再一次性切换。开发期间保留 FastAPI 作为行为对照，新后端使用隔离测试库；兼容验收通过后替换运行入口，最终移除 Python 后端。不采用按模块逐步切流的长期双后端运行方式。

用户确认直接删除 AI 历史，不导出、不归档。清理范围包括 AI 专属对话、记忆、知识库数据及向量索引、构建任务、模型配置和用量记录。业务记录、履约照片及业务附件继续保留；共享附件必须核对业务引用，共享 Outbox/通知/权限数据只能清理已确认属于 AI 的记录，不能按整表删除。

用户确认使用 Java 21 和 Maven Wrapper，并在项目构建配置中固定版本。

用户确认数据库访问层采用 MyBatis 和 Spring 事务管理。显式 SQL 应兼容现有 MySQL 表结构、条件更新、预约唯一约束、Outbox 租约领取及延迟关联分页。

用户确认数据库迁移工具采用 Flyway。已有数据库核验表结构及 Alembic 版本后显式建立 Flyway 基线，保留业务数据；新环境提供从空库初始化的 SQL 迁移。后续变更及 AI 专属数据清理通过新增迁移执行，不改写已执行 Alembic 迁移。历史 Alembic 文件保留为迁移依据，不要求切换后的 Java 系统通过 Python 执行迁移。

用户确认切换时允许短暂维护停机并要求用户重新登录。暂停业务写入，停止旧 API、Outbox Worker、Celery Worker 及相关定时任务，完成迁移与核验后启动 Spring Boot 并开放访问。保留账号与现有密码哈希，失效旧登录会话；停机时长通过迁移演练测定。

上述决策汇总于 `docs/springboot-migration-plan.md`，整体实施方案仍待用户确认。AI 清理在方案确认后的实施与切换流程中执行；当前尚未执行数据库或文件删除，也不改写已执行迁移。
