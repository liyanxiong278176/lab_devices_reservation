# 项目技术亮点

本页只记录当前 Python FastAPI 版本的非 AI 业务实现；AI 工作台保持独立，不作为本次
业务重构的验收依据。

## 1. 自然日预约与并发防超约

预约输入简化为开始日和结束日，每个设备日写入一条 `v2_reservation_day`。提交时先用
Redis 日期锁降低并发竞争，事务内再依赖 `UNIQUE(device_id, date)` 做数据库兜底。Redis
宕机不会直接让预约功能不可用，最终仍由数据库保证同一设备同一天只能有一个有效占用。

## 2. 可靠异步任务

通知、未完成交接爽约处理和候补提升都先写入同库 Outbox，再由 FastAPI 进程内异步 Worker 消费。
任务拥有唯一键、聚合键、领取租约、指数退避和最大重试次数。数据库是事实来源，WebSocket
只负责低延迟提示，断线后可以通过通知表补偿，不依赖额外消息中间件。

## 3. 学院与负责人双层数据权限

普通用户只能看到本人所属学院的设备和预约；负责人除了学院范围外，还要满足实验室负责人
或学院负责人条件才能审批、处理报修和修改设备。后端 Service 会再次校验范围，前端菜单
隐藏不被当成安全边界。

## 4. 设备生命周期与履约闭环

预约状态覆盖待审批、已通过、使用中、待归还验收、已完成、爽约和违规。审批通过后由
负责人现场交接，用户归还后由负责人验收；关键状态转换使用条件更新，维修、停用、离线和
退役设备自动从可预约集合排除，所有设备状态变化写入生命周期历史。

## 5. 深页查询与可撤销会话

预约、审批、报修、通知、设备、用户和实验室列表使用延迟关联支持页码直跳：先对稳定主键
执行 `ORDER BY id DESC` 与 `LIMIT/OFFSET`，再读取本页完整记录，并将可跳过范围限制为 100,000 条。
延迟关联减少深页的宽行读取，但 OFFSET 仍需扫描索引，因此通过硬上限和筛选提示控制最坏成本。
刷新令牌落库并轮换，旧令牌立即失效；用户禁用或改密码会撤销刷新会话，
当前请求还会重新读取数据库角色和学院信息。

## 6. 生产级输入与附件治理

报修图片只接受 JPG/PNG/WebP，单图限制 5MB，随机 token 映射到私有文件路径，并在读取时
再次校验学院范围。生产配置拒绝默认数据库密码和默认 JWT 密钥，统一错误响应包含请求 ID，
方便问题定位。
