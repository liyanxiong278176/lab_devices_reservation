# 移除 AI 并迁移至 Spring Boot

日期：2026-10-13。状态：本地迁移及兼容验收已完成；Docker 镜像拉取受环境网络限制。已确认决策见 [ADR 0041](adr/0041-springboot-migration-data-preservation.md)，实施结果见 [验证记录](springboot-verification.md)。

## 目标与范围

将当前 Python/FastAPI 后端完整迁移到 Java/Spring Boot，移除全部 AI 功能及 AI 专属历史数据。保留 Vue 3/TypeScript 前端、非 AI 功能、业务数据及 `/api/v2` 接口行为。用户此次指令覆盖现有文档中要求保留 FastAPI、禁止 Java 和保留 AI 的技术约束；其余业务、安全和可靠性约束继续适用。

新后端使用 Java 21、Maven Wrapper、MyBatis、Spring 事务管理和 Flyway。Spring Boot 与依赖的具体版本在实施时核验官方兼容矩阵后固定。继续使用 MySQL 8 和 Redis 7，保持单体应用及现有业务边界。通用后台任务仍由 MySQL Outbox 驱动；Java Worker 接替当前 Python Worker，不新增 RabbitMQ，不将通用任务改为其他队列事实源。

## 兼容要求

- 保留学院、实验室、账号、角色权限、设备资源池与实物设备、预约规则、预约审批、候补、交接、归还验收、报修、维护校准、安全检查、违规申诉、反馈、报表、业务文档和通知等现有非 AI 能力。
- 建立接口清单并比对路径、方法、输入校验、响应字段、错误码、HTTP 状态码、分页、上传下载和 SSE 协议。检查当前实际路由和服务，不以历史 Java 产物作为实现依据。
- 保留自然日预约、首尾日期包含、多台多日设备一致性和事务原子性、状态机条件更新、学院隔离与服务端权限校验。
- 保留 Cookie/JWT、Redis 会话失败关闭、Refresh Token 轮换、可信 Origin、双提交 CSRF、MySQL 账号与授权版本核验。验证现有密码哈希在 Java 中可校验，不能通过重置密码代替兼容。
- 保留 MySQL 设备日唯一约束、请求 token 幂等和请求摘要校验、Redis 名额预占及故障回退、名额对账、深分页延迟关联与最多跳过 100,000 条的限制。
- 保留 Outbox 唯一任务键、租约恢复、SKIP LOCKED、聚合键顺序、有界重试、死信及人工恢复。
- 通知历史仍来自 MySQL，Redis Streams 按 API 进程消费组分发，本地 SSE Hub 推送，Last-Event-ID 重连与最多 100 条补播继续兼容。
- 保留非 AI 上传文件、附件引用、通知序号、主键、外键、业务审计与任务状态。非 AI 监控和健康检查随 Java 运行时迁移。

## AI 移除边界

移除 AI 工作台、助手、AI 会话与记忆、知识库/RAG、知识构建、模型配置、用量及 AI 专属接口、权限、任务、配置、依赖、测试、监控与运行部署入口。移除 Qdrant 服务与本项目专属向量资源、LangChain/LangGraph 及 Celery 知识库链路。更新当前运行文档和 Agent 约束，历史设计记录保留时注明已被本方案取代。

AI 历史按用户决定直接删除，不导出、不归档。按实际模型、迁移和引用关系列出 AI 表、文件、Redis 键及 Outbox 任务清单，不以模糊名称批量删表或清空 Redis。业务设备文档、规则推荐及预约冲突替代建议按实际实现判断边界：属于非 AI 业务的能力保留。AI 工具曾创建的预约、报修等业务记录同样保留，不能因来源为 AI 而删除。

共享附件先检查业务引用；共享权限、Outbox 和通知表仅处理确定属于 AI 的记录。运行资源删除仅针对本项目专属对象，不操作共享服务中的其他项目资源。AI 专属凭据从项目运行配置中移除，不把凭据写入文档或提交。

## 实施顺序

1. 盘点当前代码、路由、表结构、迁移、任务、文件和部署入口，建立非 AI 兼容清单及 AI 清理清单。保留当前未提交改动与本地专项资料，不覆盖用户工作。
2. 在独立目录构建 Spring Boot 后端，保留 FastAPI 作行为对照；开发与自动测试使用隔离数据库和 Redis 命名空间，禁止双方 Worker 同时处理同一套业务任务。
3. 完成数据库映射、事务、认证授权、错误处理、配置与上传基础设施，逐项移植业务服务、Outbox、名额对账、Redis Streams/SSE 和监控。
4. 为现有数据库编写结构与 Alembic 版本核验及显式 Flyway 基线流程。提供空库初始化路径，后续只追加迁移；验证业务数据与约束一致性后制定 AI 清理迁移。不改写已执行 Alembic revision。
5. 移除前端 AI 入口及代码，保持非 AI 页面和接口兼容；迁移构建、部署、CI、环境模板和操作文档。历史 Alembic 文件可保留为参考，最终运行不依赖 Python 后端或 Celery。
6. 完成真实 MySQL/Redis 集成验证、浏览器验收及带业务数据的切换演练，修复兼容差异后实施一次性切换。

## 验收

Java 编译、单元测试与真实 MySQL 8/Redis 7 集成测试通过；前端 `pnpm build`、`pnpm test` 与标准 `frontend/e2e/` 的非 AI Playwright 场景通过。可用时依照 `qa_joint/README.md` 补充人工截图验收。

验证普通用户、负责人和系统管理员完整业务链、菜单权限、学院隔离、照片上传和历史文件访问。验证同设备同自然日并发只有一条占用成功，其余返回 409；验证多台多日事务、幂等重试、Redis 故障与对账、会话失败关闭、撤权、任务抢占和重复执行、Streams 分发及 SSE 补播。

迁移演练必须覆盖已有业务数据的库和全新空库，核对业务表记录、主键外键、唯一约束、索引、日期时间、密码登录和附件引用。确认 AI 入口、运行依赖及专属历史数据清除，保留现有业务数据且无残留 AI 任务不断重试。

## 切换

维护期间暂停业务写入，停止旧 API 及后台 Worker/定时任务，确保正在执行的任务安全结束或可恢复。执行数据库核验、显式基线和迁移，失效本项目旧登录会话，启动 Java API 和 Worker，通过健康及业务冒烟后开放访问，用户重新登录。

停机时长由演练测定。切换前记录业务恢复路径，涉及业务备份时排除 AI 专属历史，遵守不归档 AI 的决定。AI 清理执行后不承诺恢复 AI 历史；切换恢复只针对保留的非 AI 业务。最终移除 Python 后端运行代码与入口，保留必要历史迁移依据。
